# WaterPressureSensor

Прошивка **3.1** для Wemos D1 mini / ESP8266: измерение давления воды, OLED SSD1306, локальный веб-интерфейс и MQTT с Home Assistant Discovery. Arduino Core **3.1.2**, Espressif **NON-OS SDK 3.0.5**.

Интерфейс построен вокруг цифрового манометра с непрерывной оранжевой дугой. На компьютере показания и состояние соединений расположены рядом, на телефоне — в одной колонке с нижней навигацией. Светлая и тёмная темы доступны во всех разделах. Интернет для интерфейса не нужен.

## Подключение оборудования

| Узел | Подключение |
|---|---|
| Wemos D1 mini, 4 МБ flash | Питание через USB или подходящий стабилизированный источник |
| OLED SSD1306, 128×64, I²C | SDA → D2 / GPIO4; SCL → D1 / GPIO5; GND → GND; питание согласно модулю, сигналы I²C 3,3 В |
| OLED RESET | Не используется (`OLED_RESET = -1`); GPIO0 свободен |
| Аналоговый датчик давления | Выход → согласующая цепь → A0; общая земля с платой |
| Питание датчика | Согласно паспорту конкретного датчика; для варианта 0,5–4,5 В обычно 5 В |

Адрес OLED по умолчанию — `0x3C`. Если экран не отвечает на I²C или не удалось выделить его буфер, прошивка продолжает работу без дисплея.

### Согласование датчика 0,5–4,5 В с A0

**Не подключайте выход 4,5 В непосредственно к A0.** Производитель D1 mini указывает максимум **3,2 В** на A0. Ограничение давления в программе и индикатор `OVER` не защищают электрический вход. [Характеристики Wemos](https://www.wemos.cc/en/latest/d1/d1_mini.html).

Для платы со штатным делителем **220 кОм / 100 кОм** можно добавить **последовательный резистор 220 кОм** между выходом датчика и A0. Номиналы штатной цепи приведены на [схеме D1 mini V4](https://www.wemos.cc/en/latest/_static/files/sch_d1_mini_v4.0.0.pdf). У клонов необходимо проверить фактическую схему.

```text
Выход датчика ── 220 кОм (добавить) ── A0 ── 220 кОм (на плате) ── TOUT
                                                                  │
                                                           100 кОм (на плате)
                                                                  │
                                                                 GND
```

Расчёт для этих номиналов:

- Напряжение A0 = выход датчика × 320 / 540.
- При выходе 4,5 В на A0 будет около 2,67 В, на TOUT — 0,833 В.
- При выходе 5,0 В на A0 будет около 2,96 В.
- Напряжение датчика, соответствующее отсчёту 1023, — примерно **5,4 В**. Это значение нужно ввести в поле «Входная шкала АЦП».

Применяйте резистор с допуском 1%, проверьте напряжение мультиметром до подключения A0 и выполните калибровку. Расчёт не учитывает погрешности АЦП, резисторов и выходное сопротивление датчика. Для длинных проводов и помех требуется отдельно продумать фильтрацию и защиту входа.

Существующие настройки при обновлении сохраняются. Значение по умолчанию `adcFullScaleV = 3.2` оставлено для совместимости: после установки внешнего резистора замените его на фактическую шкалу цепи, например 5,4 В.

## Сборка и первый запуск

Нужен PlatformIO Core или расширение PlatformIO для VS Code. Версии платформы и библиотек закреплены в `platformio.ini`; окружение по умолчанию — `d1_mini`.

NON-OS SDK 3.0.5 выбирается штатным флагом Arduino из закреплённого пакета framework. Отдельная загрузка или подмена SDK не требуется. Подробности и проверка фактической версии: [SDK 3.0.5](docs/NONOS_SDK_3.0.5.md).

```sh
pio run -e d1_mini
pio run -e d1_mini -t upload
pio device monitor -b 115200
```

Вторая команда загружает прошивку на подключённую плату. При нескольких последовательных портах добавьте `--upload-port COM5` с нужным портом.

1. Начальный пароль точки доступа и интерфейса — **`water1234`**. Текущий пароль также выводится в USB Serial строкой `[portal] пароль интерфейса и точки доступа: …`. Ранее сохранённый пароль не меняется при обновлении прошивки.
2. Подключитесь к сети `WaterSensor-xxxxxx` с этим паролем. В режиме настройки OLED также показывает SSID, пароль и адрес.
3. Откройте в Chrome `http://192.168.4.1/`. Если телефон сообщает, что у сети нет интернета, сохраните подключение к ней.
4. Нажмите значок замка и войдите с тем же паролем.
5. В разделе **Подключение** выберите домашнюю сеть 2,4 ГГц. MQTT можно настроить сразу или позже; пустой адрес брокера выключает MQTT.
6. В разделе **Калибровка** проверьте параметры датчика и согласующей цепи.

После подключения интерфейс доступен по IP устройства или `http://wps-xxxxxx.local/`, если сеть и клиент поддерживают mDNS. IP показан на OLED и в веб-интерфейсе; его также можно найти в DHCP-списке роутера.

### Восстановление Wi-Fi

Подключение к сети выполняется без ожидания в `setup()`. При потере Wi-Fi через 15 секунд предлагается резервная AP. При сохранённой сети и отсутствии клиентов AP закрывается через 180 секунд; без сохранённой сети работает постоянно. После успешного подключения к роутеру AP закрывается, когда клиентов нет и прошло хотя бы 10 секунд с её запуска.

Перед каждой новой попыткой применяется подход Tasmota: текущая конфигурация SDK
очищается **только в RAM**, STA выключается, после паузы **не менее 200 мс** заново
включается и получает явные SSID и пароль. Пауза отсчитывается после завершения
выключения STA и не блокирует рабочий цикл. Копия SSID/пароля хранится в менеджере;
сохранённая сеть во flash и резервная AP при повторе не стираются.

Подключение считается успешным только при наличии `WL_CONNECTED` и ненулевого IP.
SDK может восстановить связь самостоятельно; если этого не произошло за 30 секунд,
повторяется очистка RAM и запуск STA без привязки к прежнему каналу или BSSID.
Повторы идут и после закрытия резервной AP. Новая сеть из веб-формы записывается
во flash один раз при применении; последующие повторы flash не записывают.
При восстановлении IP заново запускаются HTTP и mDNS, затем MQTT продолжает обычное подключение.
Измерения продолжаются офлайн; потеря Wi-Fi сама по себе не вызывает перезагрузку.
Если резервная AP уже закрылась, перезапуск платы снова откроет окно настройки.

## Веб-интерфейс

| Раздел | Возможности |
|---|---|
| Обзор | Манометр в барах, значение в МПа, Wi-Fi, MQTT, состояние датчика, напряжение, АЦП и память |
| Подключение | Поиск Wi-Fi, подключение к сети, MQTT, Home Assistant Discovery, TLS, загрузка и удаление CA |
| Калибровка | Четыре параметра пересчёта и предварительный расчёт измеримого диапазона |
| Устройство | Версия, адрес, время работы, имя, пароль интерфейса, OTA и перезагрузка |

Тема при первом открытии следует системной настройке, затем сохраняется отдельно в браузере. Все шрифты, иконки и скрипты локальные; CDN, внешних библиотек графиков и облачного сервиса нет.

Опрос выполняется раз в 2 секунды без параллельных запросов статуса и останавливается в скрытой вкладке. Через 5 секунд без свежего ответа число на манометре заменяется на «—». Ошибка сигнала, переполнение диапазона и устаревшее измерение отображаются отдельно. Черновики форм не перезаписываются фоновым обновлением.

Оранжевая дуга показывает долю измеримого диапазона. Зелёный статус означает корректность сигнала, **а не безопасность давления в системе**. Управления насосом, аварийной автоматики и хранения истории в прошивке нет.

### Доступ к настройкам

При открытии окна **Вход в настройки** OLED временно показывает текущий пароль интерфейса. После успешного входа или закрытия окна крестиком возвращается прежний экран. Неверный пароль оставляет окно и подсказку открытыми. Экран режима настройки точки доступа по-прежнему показывает её SSID, пароль и адрес.

Просмотр состояния публичный в локальной сети. Изменение настроек, загрузки, удаление CA и перезагрузка требуют входа. Сессия действует час с момента входа; новый вход заменяет предыдущую сессию. Cookie имеет `HttpOnly` и `SameSite=Strict`, изменяющие запросы дополнительно требуют заголовок интерфейса.

MQTT-пароль и пароль интерфейса не возвращаются API настроек. Пустое поле нового MQTT-пароля сохраняет прежний; для удаления предусмотрен отдельный флажок. Пароль резервной AP меняется после перезапуска устройства.

У всех пяти полей пароля есть кнопка с глазом: она показывает или скрывает **введённое значение**. Пароли, уже сохранённые на устройстве, с сервера не запрашиваются. При выходе из интерфейса введённые пароли очищаются, даже если были раскрыты. Новый пароль интерфейса может содержать 8–63 печатных символа ASCII без пробелов; начальный `water1234` можно изменить в разделе **Устройство**.

Веб-интерфейс работает по **HTTP**, поэтому его следует использовать в доверенной локальной сети без проброса наружу. Пароли хранятся в flash без шифрования. TLS из следующего раздела защищает соединение с MQTT-брокером, а не HTTP-интерфейс.

## Измерение и калибровка

Один отсчёт A0 берётся примерно каждые 20 мс. Давление рассчитывается по скользящему среднему 32 отсчётов, номинальное окно — 0,64 секунды. После паузы в выборке от 500 мс старое окно заменяется свежим отсчётом.

```text
Vдатчика = raw / 1023 × adcFullScaleV
P, МПа  = (Vдатчика − vZero) × pFullMPa / (vFull − vZero)
P, бар  = P, МПа × 10
Pmax    = (min(adcFullScaleV, vFull) − vZero) × pFullMPa / (vFull − vZero) × 10
```

| Параметр | Значение по умолчанию | Допустимое значение |
|---|---:|---|
| `adcFullScaleV` | 3,2 В | 1–10 В; напряжение датчика до внешнего делителя при отсчёте 1023 |
| `vZero` | 0,5 В | Не меньше 0 и ниже `adcFullScaleV` |
| `vFull` | 4,5 В | Не больше 10 В и выше `vZero` более чем на 0,1 В |
| `pFullMPa` | 0,5 МПа | Больше 0, не больше 100 МПа; берётся с маркировки датчика |

В форме принимаются только конечные числа. Некорректный запрос отвергается целиком. В частности, `1e99`, `null`, строки вместо чисел и неизвестные поля не превращаются в сохранённую калибровку.

При исходных коэффициентах расчётная граница — 3,375 бар; индикатор насыщения срабатывает немного раньше отсчёта 1023. Для цепи с `adcFullScaleV = 5.4` и датчика 0,5 МПа измеримая шкала ограничена самим датчиком: 5 бар.

- `over`: хотя бы один свежий отсчёт достиг 1020 либо восстановленное напряжение превысило `vFull + 0.05 В`.
- `fault`: напряжение ниже `vZero − 0.2 В`, недопустимый отсчёт или неконечный результат пересчёта. Это проверка сигнала; она не определяет однозначно причину неисправности.
- Кратковременные нарушения проверяются **до усреднения**. Флаг снимается после секунды устойчивого сигнала с гистерезисом; длинная пауза в измерении не считается восстановлением.
- `stale`: отсчёта ещё нет либо его возраст достиг 1000 мс.

При `over`, `fault` или `stale` давление в JSON равно `null`. Диагностические напряжение и АЦП остаются доступны вместе с возрастом отсчёта. Небольшое отрицательное давление сохраняется как результат калибровки, а не обрезается до нуля.

## MQTT и Home Assistant

По умолчанию MQTT выключен. Основные параметры:

| Параметр | Значение / ограничение |
|---|---|
| Адрес | DNS-имя или IPv4 без схемы и порта; до 63 байт |
| Порт | 1–65535; стандартно 1883 без TLS или 8883 с TLS |
| Пользователь / пароль | До 31 / 63 байт UTF-8 |
| База топиков | `watersensor/wps_xxxxxx`; до 63 байт |
| Период публикации | 10 секунд; диапазон 1–3600 |
| Префикс Discovery | `homeassistant`; пустой выключает Discovery; до 31 байта |
| Имя устройства | До 31 байта UTF-8, поэтому кириллица занимает больше места |

База и префикс не допускают `+`, `#`, управляющих символов и завершающего `/`. Автоматическая смена порта в форме применяется только к стандартной паре 1883/8883; перед сохранением можно указать свой порт.

Топики:

```text
<base>/state                                  JSON показаний, без retain
<base>/status                                 online/offline, retain; offline также LWT
<haPrefix>/sensor/<deviceId>/<entity>/config    retained Discovery
```

Сущности Discovery: `pressure`, `voltage`, `rssi`, `raw`. Для них задан срок актуальности `3 × mqttIntervalS + 10` секунд. После соединения отправляется свежий отсчёт без ожидания очередного периода.

При смене префикса прошивка удаляет прежние retained-конфигурации. Неудачная отправка или сохранение не стирает память о старом префиксе; операция повторяется. PubSubClient публикует с QoS 0, поэтому успешный `publish()` означает передачу в транспорт, а не подтверждение хранения брокером. При смене самого брокера прежние записи на старом брокере нужно удалить отдельно.

Ошибки аутентификации или запрет со стороны брокера останавливают повторы до сохранения настроек. Временные ошибки повторяются с растущей паузой до 30 секунд после завершения попытки.

В Serial на скорости 115200 сообщения содержат этап, адрес брокера, причину и подсказку:

```text
[MQTT][DNS] Не найден адрес брокера 'mqtt.example.invalid'. Проверьте написание имени, DNS роутера или укажите IP вместо имени.
[MQTT][ERROR] 192.168.1.10:1883, код 4: Брокер отклонил логин или пароль MQTT.
[MQTT][CHECK] Проверьте пользователя и пароль в разделе Подключение; пустое поле сохраняет прежний пароль.
[MQTT][PAUSED] Повторы остановлены. Исправьте настройки в веб-интерфейсе и нажмите Сохранить MQTT.
```

Коды `-2` и `-4` различают неудачное открытие соединения и отсутствие ответа MQTT; они сами по себе не доказывают неправильность пароля. Код `4` означает отказ в учётных данных, `5` — отказ в доступе, `3` — временную недоступность сервиса. При коде `5` проверяйте и логин/пароль, и права: проверенный брокер возвращал этот код также при неверном имени пользователя. При ошибках TLS дополнительно выводятся строки `[TLS][ERROR]` и `[TLS][CHECK]`, при ожидании NTP — `[TLS][TIME]`. Пароль MQTT в журнал не выводится.

### Режимы TLS

| Режим | Проверка |
|---|---|
| Без TLS | Незашифрованный MQTT |
| TLS без проверки | Шифрование без проверки подлинности брокера; выбирается явно |
| TLS по отпечатку | SHA-1 сертификата: 40 hex-символов или 20 пар через двоеточия |
| TLS по CA | Доверенный CA, имя брокера и срок действия сертификата; нужны часы NTP |

Неверный отпечаток или неизвестный режим блокирует подключение: автоматического перехода к менее строгой проверке нет. TLS подключается через имя хоста, которое BearSSL использует для SNI и проверки сертификата. Для CA используйте DNS-имя из сертификата и загрузите корневой сертификат в PEM, не больше **4096 байт**. Закрытый ключ загружать не нужно.

В режиме CA сервер времени по умолчанию — `pool.ntp.org`; в изолированной сети укажите свой NTP. До установки часов MQTT ожидает синхронизации. При пиннинге после перевыпуска сертификата потребуется обновить отпечаток.

Прошивка проверяет поддержку MFLN: при её наличии приёмный буфер TLS составляет 1024 байта, иначе — 16384. Перед рукопожатием контролируется размер свободного непрерывного блока памяти. Детали ограничений BearSSL описаны в [документации ESP8266 Arduino Core 3.1.2](https://arduino-esp8266.readthedocs.io/en/3.1.2/esp8266wifi/bearssl-client-secure-class.html).

**Попытки MQTT/TLS остаются синхронными.** DNS, TCP и рукопожатие могут задерживать HTTP, OLED и выборку АЦП на несколько секунд. Указанные в `Config.h` таймауты не дают строгой общей верхней границы. После задержки фильтр обновляется свежим отсчётом; прошивка не восстанавливает пропущенные измерения. Для регистрации быстрых гидроударов нужна другая схема сбора данных.

## HTTP API

| Метод и путь | Назначение |
|---|---|
| `GET /reading` | Показания в формате MQTT |
| `GET /api/status` | Показания, соединения, диагностика и состояние входа |
| `POST /api/login` | JSON `{ "password": "…" }`; устанавливает cookie |
| `POST /api/logout` | Завершение сессии |
| `GET /api/settings` | Настройки без паролей, требуется вход |
| `POST /api/settings` | Частичное обновление; проверяется и сохраняется целиком |
| `POST /api/wifi` | `ssid`, `password`, `keepPassword` |
| `POST /api/wifi/scan` | Запустить поиск сетей |
| `GET /api/wifi/scan` | Результат поиска |
| `POST /api/ca` | Multipart-файл PEM |
| `POST /api/ca/delete` | Удалить CA |
| `POST /api/firmware` | Multipart-файл прошивки |
| `POST /api/restart` | Перезапуск после отправки ответа |

Все POST требуют `X-WPS-Request: 1`; кроме входа, нужна действующая сессия. Результат — JSON с `message` или `error`. API не разрешает CORS. Размер JSON-запроса ограничен 2048 байтами при разборе.

Пример `GET /reading`:

```json
{"bar":2.55,"mpa":0.255,"volt":2.540,"raw":812,"rssi":-58,"over":false,"fault":false,"heap":24568,"raw_instant":813,"age_ms":8,"stale":false}
```

`raw` — средний АЦП, `raw_instant` — последний отсчёт, `volt` — восстановленное напряжение датчика до внешнего делителя, `age_ms` — возраст последнего отсчёта, `heap` — свободные байты памяти.

## Сохранение и обновление

Настройки находятся в LittleFS: `/config.json`, CA — `/ca.pem`. Wi-Fi хранится средствами ESP8266 SDK. Настройки прежней версии читаются; если пароль отсутствует или недопустим для точки доступа, устанавливается начальный `water1234`. Сохранённый корректный пароль, включая сгенерированный версией 3.0.0, сохраняется.

Настройки сначала записываются в `/config.tmp`. Проверяются ожидаемая длина JSON, фактический размер, возможность разбора и точное совпадение записанных байтов. Только затем выполняется замена через `rename`. При ошибке активные настройки в RAM и рабочий файл сохраняются, интерфейс показывает ошибку.

CA также записывается во временный файл, проверяется по размеру и разбирается BearSSL перед заменой. Рабочий файл не удаляется заранее. Атомарность `rename` обеспечивается [LittleFS](https://github.com/littlefs-project/littlefs).

При старте автоматическое форматирование допускается только для полностью стёртого раздела. Если существующий раздел не монтируется, прошивка сохраняет его для восстановления, работает с временными настройками и показывает ошибку. При неисправности flash пароль, напечатанный после запуска, может не сохраниться между перезагрузками.

### OTA из браузера

1. Соберите `pio run -e d1_mini`.
2. Откройте **Устройство → Обновление прошивки** и выберите `.pio/build/d1_mini/firmware.bin`.
3. Подтвердите загрузку и дождитесь завершения. Устройство проверит файл средствами ESP8266 Updater и перезапустится.
4. После восстановления связи проверьте версию. Если ответ потерялся, сначала проверьте установленную версию, затем решайте, повторять ли загрузку.

HTML/CSS/JS сжимаются скриптом `scripts/embed_web.py` и включаются в firmware как PROGMEM. **Отдельная загрузка файловой системы (`uploadfs`) для интерфейса не нужна.** Обычное обновление приложения с прежней разметкой flash сохраняет настройки и CA. Полное стирание flash или запись образа LittleFS их удаляет.

## Разработка и проверки

```text
src/Logic.*       Формулы, фильтр, валидация, JSON и логика Discovery
src/Sensor.*      Получение отсчётов A0
src/Settings.*    Хранение настроек
src/CaStore.*     Проверка и замена CA
src/Mqtt.*        MQTT, TLS и переподключение
src/Portal.*      Wi-Fi, HTTP API, вход и OTA
src/Display.*     OLED
src/main.cpp      Порядок применения настроек и планировщик
web/              Исходные HTML, CSS и JavaScript
scripts/          Упаковка, локальный предпросмотр и проверка Chrome
test/             Native-тесты и имитация сбоев файловой системы
```

Проверки прошивки без платы:

```sh
pio test -e native
pio run -e d1_mini
python scripts/verify_nonos_sdk.py
```

Native-тесты покрывают калибровку, JSON, отпечатки, скачки и обрывы сигнала, устаревание, переполнение `millis()`, повтор Discovery и сбои записи. Для Wi-Fi проверяются пауза после фактического выключения STA, длительное отсутствие роутера, повторное применение той же сети, сохранность flash и AP, ошибки SDK и отсутствие IP. Тест хранилища компилирует производственный код с имитацией файловой системы; криптографический разбор PEM в этом тесте заменён заглушкой.

Локальный предпросмотр:

```sh
python scripts/preview.py
```

Откройте `http://127.0.0.1:8765/`, пароль **`preview-access123`**. Это отдельный демонстрационный сервер с явно обозначенными тестовыми данными; он не подключается к плате. Для другого порта используйте `--port 8766`.

Для браузерного теста нужен Node.js, установленный Google Chrome и доступный Node-модуль `playwright`:

```sh
node scripts/ui_smoke.cjs
```

Тест запускает отдельный headless Chrome, проверяет четыре раздела в двух темах на ширинах 360, 390, 768, 1280 и 1440 пикселей, вход, формы, пять кнопок просмотра пароля, очистку раскрытых паролей при выходе, сохранность черновика, ошибки измерений и восстановление связи. Скриншоты записываются в `.pio/ui-review/`. Адрес предпросмотра можно изменить через переменную `WPS_PREVIEW_URL`.

Версия 3.0.1 также проверена на ESP8266 с COM4: USB-прошивка, реальные страницы в Chrome, запуск AP, сохранение после перезагрузки и ошибки MQTT. Результаты и границы проверки: [отчёт испытаний 3.0.1](docs/TEST_REPORT_3.0.1.md).

Версия 3.0.3 с SDK 3.0.5 установлена через COM6: проверены Wi-Fi, MQTT/TLS, сохранность настроек, Chrome на компьютере и телефоне и перезапуск из веб-интерфейса. Результаты и границы проверки: [проверка SDK 3.0.5](docs/NONOS_SDK_3.0.5.md).

Версия **3.1** установлена через веб-обновление на **192.168.1.68** 25 октября 2026 года. Прошли **154 native-теста**, три повторных подключения Wi-Fi с восстановлением MQTT/TLS, проверка настроек, Chrome и перезапуска. Перезагрузка роутера не выполнялась: пользователь не мог провести её в это время. Подробности и SHA-256: [отчёт испытаний 3.1](docs/TEST_REPORT_3.1.md).

GitHub Actions выполняет native-тесты, сборку D1 mini и проверку версии SDK в бинарном файле и происхождения библиотек по карте линковки. Браузерная проверка выполняется отдельно. Ни успешная сборка, ни mock-тесты не заменяют проверку на плате: перед эксплуатацией следует проверить реальное напряжение A0, калибровку, TLS своего брокера, отключение Wi-Fi, сохранение после перезапуска и OTA.

## Что исправлено в 3.0.0

- Полностью заменён веб-портал; все страницы адаптированы для Chrome на компьютере и телефоне, добавлены две темы.
- Настройки применяются до следующего `mqttLoop`; TLS использует указатель правильного типа и подключение с именем хоста.
- Удалён неявный переход к TLS без проверки при неправильном отпечатке.
- Исключено успешное подтверждение неполной записи JSON; настройки меняются только после успешного сохранения.
- Рабочий CA сохраняется при ошибке загрузки или переименования.
- Короткие выходы за диапазон обнаруживаются до усреднения, после сетевых задержек берётся свежий отсчёт.
- Ошибки отправки Discovery повторяются с сохранением прежнего префикса.
- Отклоняются бесконечные и некорректные коэффициенты калибровки.
- Исправлено переполнение `deviceName` в тесте MQTT; проверяется размер всего MQTT-пакета вместе с топиком.
- Защищены настройки и OTA, убран общий пароль AP, отключено форматирование существующего раздела при ошибке монтирования.
- Документация подключения заменена схемой согласования с учётом встроенного делителя D1 mini.

## Изменения в 3.0.1

- Простой начальный пароль AP и интерфейса `water1234`; пользовательский пароль от 8 символов.
- Кнопки просмотра пароля в формах входа, Wi-Fi, MQTT, смены пароля и его подтверждения.
- Понятные сообщения MQTT в Serial: причина, адрес, код, действие для пользователя и состояние повторных попыток.

## Изменения в 3.0.2

- При открытии окна входа в настройки пароль интерфейса временно выводится на OLED. Успешный вход или закрытие крестиком возвращают прежний экран. Режим настройки точки доступа работает как прежде.

## Изменения в 3.0.3

- NON-OS SDK обновлён с `2.2.2-dev(38a443e)` до штатного **3.0.5(b29dcd3)** из Arduino Core 3.1.2.
- Добавлена проверка версии SDK в бинарнике и происхождения библиотек по карте линковки.
- Реальная версия SDK выводится при старте в Serial и в `/api/status` полем `sdk`; поле `sdk_release` указывает релиз источника.
- Исправлено немедленное закрытие резервной AP из-за устаревшей отметки времени при расчёте её возраста.
- Повторы подключения Wi-Fi остаются каждые 30 секунд. Устранение исходного таймаута WPA после перезапуска роутера требуется подтвердить отдельным испытанием.

## Изменения в 3.1

- Перед начальным подключением, сменой сети и повтором очищается текущая конфигурация SDK в RAM, как в Tasmota; затем явно применяются сохранённые SSID и пароль.
- Пауза после фактического выключения STA — не менее 200 мс без блокирующего `delay()`; работа измерений и резервной AP продолжается.
- Для успешного подключения требуются статус `WL_CONNECTED` и ненулевой IP; новые настройки не теряются при ошибке включения STA.
- Закрытие резервной AP не включает STA раньше завершения паузы. Пароль и SSID доступны менеджеру, даже когда SDK временно очищен.
- При повторном сохранении той же сети сначала восстанавливается конфигурация RAM: оптимизация Arduino Core, пропускающая неизменившуюся запись flash, больше не оставляет STA без SSID и пароля.
- Arduino Core **3.1.2** и NON-OS SDK **3.0.5(b29dcd3)** сохранены.
