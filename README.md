# WaterPressureSensor

Датчик давления воды на Wemos D1 mini: показания на OLED-экране, настройка через
веб-портал, передача в MQTT с автоматической регистрацией в Home Assistant.

## Железо

| Узел | Подключение |
|---|---|
| Wemos D1 mini (ESP8266) | — |
| OLED SSD1306 128x64, I²C | SDA → D2 (GPIO4), SCL → D1 (GPIO5), адрес `0x3C` |
| Датчик давления XIDIBEI, G1/4 | выход → **A0 напрямую**, без делителя |

Датчик: [XIDIBEI на AliExpress](https://aliexpress.ru/item/4000760954688.html)

### Про прямое подключение к A0 и границу диапазона

Датчик выдаёт 0.5–4.5 В на свой полный диапазон давления. У Wemos D1 mini вход A0 —
не голый вывод TOUT: на плате стоит делитель 220 кОм / 100 кОм, поэтому **3.2 В
на пине A0 соответствуют отсчёту 1023**.

Отсюда верхняя граница измерения при полной шкале датчика 0.5 МПа:

```
(3.2 В − 0.5 В) / 8 В/МПа = 0.3375 МПа ≈ 3.37 бар
```

Для системы, где давление не превышает 0.3 МПа, этого хватает с запасом около 11%.
Прошивка показывает `OVER` и публикует `"over": true`, когда АЦП упирается в потолок,
и не выдаёт заведомо неверное число.

> **Важно.** Выше ~0.34 МПа схема не просто перестаёт мерить: на вход приходит больше
> абсолютного максимума. При 0.5 МПа датчик выдал бы 4.5 В, то есть ~1.4 В на TOUT при
> допустимом ~1.1 В. Программно от этого защититься нельзя. Если в системе возможен
> аварийный скачок давления, поставьте внешний делитель или стабилитрон — и после этого
> пересчитайте поле «Напряжение на A0 при отсчёте 1023» на портале.

## Первый запуск

1. Прошейте плату: `pio run -t upload`.
2. Устройство поднимет точку доступа **`WaterSensor-xxxxxx`**, пароль **`pressure123`**
   (константа `PORTAL_AP_PASSWORD` в [src/Config.h](src/Config.h)). SSID, пароль и адрес
   портала показываются на экране.
3. Подключитесь к ней — портал откроется сам, либо зайдите на `http://192.168.4.1/`.
4. **Setup** — задайте брокер MQTT и, при необходимости, калибровку. Сохраните.
5. **Configure WiFi** — выберите домашнюю сеть. После сохранения устройство подключится
   и покажет свой IP.

Если за 3 минуты никто не настроил портал, устройство продолжит работу офлайн: экран и
измерения работают, WiFi переподключается сам.

## Изменение настроек потом

Портал остаётся доступен всё время работы по адресу устройства: `http://<IP>/` или
`http://wps-xxxxxx.local/`. Страница **Setup** меняет MQTT и калибровку, не трогая
сохранённые учётные данные WiFi. Перепрошивка и сброс настроек для этого не нужны.

## Поля настроек

### MQTT

| Поле | По умолчанию | Смысл |
|---|---|---|
| Адрес брокера | пусто | **Пусто = MQTT выключен**, устройство работает автономно |
| Порт | `1883` | |
| Пользователь / Пароль | пусто | Пусто = подключение без аутентификации |
| Базовый топик | `watersensor/wps_xxxxxx` | Префикс всех топиков устройства |
| Период публикации | `10` с | 1–3600 |
| Имя устройства в Home Assistant | `Water Pressure` | Как устройство назовётся в HA |
| Префикс discovery | `homeassistant` | **Пусто = не публиковать discovery** |

### Калибровка

| Поле | По умолчанию | Смысл |
|---|---|---|
| Напряжение на A0 при отсчёте 1023 | `3.2` В | Делитель платы D1 mini |
| Выход датчика при нулевом давлении | `0.5` В | Нижняя точка кривой датчика |
| Выход датчика при полной шкале | `4.5` В | Верхняя точка кривой датчика |
| Полная шкала датчика | `0.5` МПа | **Проверьте по маркировке своего датчика** |

Пересчёт:

```
volts = raw / 1023 * adcFullScaleV
mpa   = (volts - vZero) * pFullMPa / (vFull - vZero)
bar   = mpa * 10
```

Недопустимые значения (например, `vFull` ≤ `vZero`) откатываются к значениям по умолчанию
при загрузке — деление на ноль в пересчёте невозможно.

### Как откалибровать

1. **Ноль шкалы платы.** Измерьте мультиметром напряжение между A0 и GND, сравните с
   `volts` в MQTT (поле `volt`). Расхождение убирается полем «Напряжение на A0 при
   отсчёте 1023»: новое значение = старое × (измеренное / показанное).
2. **Ноль датчика.** При нулевом давлении в системе посмотрите `volt`. Это и есть
   фактический `vZero` — впишите его.
3. **Наклон.** Сверьте показания с манометром при известном давлении. Если наклон
   не сходится, подстройте «Полная шкала датчика».

## MQTT

Базовый топик далее — `<base>`, по умолчанию `watersensor/wps_xxxxxx`.

| Топик | Retained | Содержимое |
|---|---|---|
| `<base>/status` | да | `online` / `offline` (последняя воля) |
| `<base>/state` | нет | JSON, раз в период публикации |
| `<haPrefix>/sensor/<id>/{pressure,voltage,rssi,raw}/config` | да | Discovery Home Assistant |

Пример `<base>/state`:

```json
{"bar":2.47,"mpa":0.247,"volt":2.47,"raw":812,"rssi":-58,
 "over":false,"fault":false,"heap":24568}
```

- `bar` и `mpa` публикуются как `null`, если `over` или `fault`: давление в этот момент
  неизвестно, и график в Home Assistant не должен показывать выдуманное число.
- `volt` и `raw` публикуются всегда — они измерены честно и помогают понять причину.
- `heap` — свободная куча, для диагностики.

### Home Assistant

При непустом префиксе discovery устройство регистрируется само — правки
`configuration.yaml` не нужны. Появляются четыре сущности, собранные в одно устройство:
давление (`bar`), напряжение датчика, уровень сигнала WiFi и сырой отсчёт АЦП;
последние две — диагностические.

Проверить публикацию:

```
mosquitto_sub -h <брокер> -t 'watersensor/#' -v
```

## Экран

Рабочий режим — крупное давление в барах, ниже значение в МПа и строка состояния
(`W:ok`/`W:--` — WiFi, `M:ok`/`M:--`/`M:off` — MQTT).

Особые состояния:

| Экран | Причина |
|---|---|
| `NO SENSOR` | Напряжение ниже минимума датчика — обрыв или датчик не подключён |
| `OVER` | АЦП упёрся в потолок, давление выше измеримого диапазона |

Если дисплей не отвечает по I²C, прошивка продолжает работать без него: измерения и
публикация в MQTT от экрана не зависят.

## Сборка

```
pio run              # собрать
pio run -t upload    # прошить
pio device monitor   # лог, 115200
```

Настройки хранятся в `/config.json` на LittleFS и переживают перепрошивку.
Учётные данные WiFi хранит SDK ESP8266 отдельно.

## Тесты

```
pio test -e native
```

71 тест, выполняются на компьютере — плата не нужна. Покрыта вся вычислительная
логика прошивки, собранная в [src/Logic.cpp](src/Logic.cpp): пересчёт отсчёта АЦП
в давление, валидация настроек, сборка MQTT-топиков и payload.

| Набор | Что проверяет |
|---|---|
| [test/test_pressure](test/test_pressure) | Арифметика датчика: опорные точки кривой, монотонность, линейность, границы флагов `over` и `fault`, произвольная калибровка, отсутствие NaN на всём диапазоне 0–1023 |
| [test/test_settings](test/test_settings) | Значения по умолчанию и валидация: сброс недопустимых полей, обрезка хвостовых `/` в топике, сохранение пустого префикса discovery, идемпотентность, гарантия отсутствия деления на ноль |
| [test/test_mqtt](test/test_mqtt) | Топики и payload: точный JSON состояния, `null` вместо давления при `over`/`fault`, поля discovery, и главное — что discovery-payload помещается в буфер PubSubClient |

Ключевые тесты, каждый закрывает конкретный способ сломать устройство:

- `test_sanitize_always_yields_usable_math` — перебирает испорченные комбинации
  калибровки (нули, отрицательные, NaN, 1e9) и требует, чтобы после валидации
  пересчёт давал конечные числа. Без этой гарантии `vFull == vZero` даёт деление
  на ноль в рабочем цикле.
- `test_discovery_fits_in_publish_buffer` — у PubSubClient буфер фиксированный, и
  при переполнении `publish()` возвращает `false` молча: устройство просто не
  появится в Home Assistant. Тест проверяет все четыре сущности с нарочно длинными
  именем устройства и базовым топиком.
- `test_empty_ha_prefix_is_preserved` — регрессия на реальную ошибку: валидация
  возвращала пустому префиксу значение по умолчанию, и выключенный discovery
  включался обратно после перезагрузки.

Тесты собираются окружением `[env:native]` и компилируют только `src/Logic.cpp` —
остальные модули завязаны на железо. На Windows системного gcc обычно нет, поэтому
[scripts/native_toolchain.py](scripts/native_toolchain.py) подставляет mingw-w64,
который PlatformIO уже держит у себя, и линкует статически.

Логика работы с железом — WiFiManager, PubSubClient, отрисовка OLED — юнит-тестами
не покрыта: её проверка требует мокать сеть и I²C, что было бы хрупче самого кода.
Чек-лист ручной проверки на плате — в разделе «Первый запуск».
