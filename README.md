# WaterPressureSensor

Прошивка **3.1.1** для **Wemos D1 mini / ESP8266**. Измеряет давление по сигналу A0, показывает его на OLED SSD1306 и в локальном браузере, публикует MQTT и конфигурацию Home Assistant Discovery. Настройки, сертификат CA и обновление прошивки доступны через веб-интерфейс.

Измерения работают без MQTT и Wi-Fi. Истории показаний, управления насосом и аварийной автоматики нет. Индикатор корректного сигнала означает измеримость показания, а не безопасность давления в системе.

## Платформа и сборка

Версия прошивки, окружения и зависимости определены в [platformio.ini](platformio.ini).

| Компонент | Значение |
|---|---|
| Основное окружение | `d1_mini` |
| PlatformIO platform | `espressif8266@4.2.1` |
| Framework | Arduino Core 3.1.2, пакет `3.30102.0` |
| NON-OS SDK | Штатный 3.0.5; флаг `PIO_FRAMEWORK_ARDUINO_ESPRESSIF_SDK305` |
| Adafruit GFX / SSD1306 / BusIO | 1.12.6 / 2.5.17 / 1.17.4 |
| PubSubClient / ArduinoJson | 2.8 / 7.4.3 |
| Serial / файловая система | 115200 бод / LittleFS |

Установите PlatformIO Core или расширение PlatformIO для VS Code. Из корня проекта:

```sh
pio run -e d1_mini
pio run -e d1_mini -t upload --upload-port COM4
pio device monitor -p COM4 -b 115200
```

Замените `COM4` фактическим портом платы. Если `pio` отсутствует в PATH, используйте `python -m platformio` из Python-окружения с установленным PlatformIO.

Результат — `.pio/build/d1_mini/firmware.bin`. Скрипт `scripts/embed_web.py` сжимает HTML/CSS/JS из [web](web) и включает их в приложение как PROGMEM. **Загрузка файловой системы `uploadfs` для интерфейса не требуется.**

Окружение `d1_mini_diag` добавляет диагностику Wi-Fi и суффикс версии `-diag-sdk305`. Обычная сборка диагностический журнал не ведёт.

## Первый запуск

1. Откройте Serial 115200: там выводятся версия, SDK, сообщения Wi-Fi и строка `[portal] пароль интерфейса и точки доступа: …`.
2. Если сохранённой сети нет, подключитесь к `WaterSensor-xxxxxx`. Начальный пароль — **`water1234`**. Корректный ранее сохранённый пароль при обновлении не заменяется.
3. Откройте `http://192.168.4.1/`. На телефоне сохраните подключение, если система предупреждает об отсутствии интернета.
4. Нажмите значок замка и войдите с паролем интерфейса.
5. В разделе **Подключение** задайте сеть 2,4 ГГц и при необходимости MQTT/TLS.
6. В разделе **Калибровка** проверьте коэффициенты своего датчика и входной цепи.

При сохранённой сети сначала начинается подключение к ней; резервная AP предлагается через 15 секунд отсутствия связи. Она не обязана появляться немедленно при каждом старте.

После подключения к роутеру найдите STA-IP в Serial, DHCP-списке роутера или веб-интерфейсе. Имя `http://wps-xxxxxx.local/` работает при поддержке mDNS сетью и клиентом. `xxxxxx` — шестизначный chip ID. Рабочий OLED не показывает STA-IP; адрес на экране `SETUP MODE` относится к резервной AP.

### Доступ и пароли

Показания и статус доступны без входа. Настройки, поиск и смена Wi-Fi, загрузки, удаление CA и перезапуск требуют сессии. Сессия действует час с момента входа. Новый успешный вход заменяет предыдущую сессию; смена пароля интерфейса её аннулирует. Между попытками входа выдерживается минимум 3 секунды.

Открытие окна входа временно показывает пароль на OLED. Видимая вкладка с открытым окном продлевает показ каждые **20 секунд**. Вход, закрытие окна и переход вкладки в фон отправляют запрос скрытия. Если браузер закрыт, сеть потеряна или запрос не дошёл, через **60 секунд без продления** устройство возвращает обычный экран: показания либо `SETUP MODE` в зависимости от состояния AP. Отсутствие OLED не останавливает измерения.

Кнопки с глазом раскрывают только введённые значения. Сохранённые пароли MQTT и интерфейса API не возвращает. Явный выход очищает и скрывает введённые пароли.

Пароль интерфейса: **8–63 печатных ASCII-символа без пробелов**. Уже работающая AP сохраняет прежний пароль; следующая создаваемая AP использует текущее значение настроек. После перезапуска пароли интерфейса и AP совпадают. До перезапуска подсказка OLED может содержать новое значение: для ранее запущенной AP используйте прежний пароль.

Веб-интерфейс работает по **HTTP**; пароли хранятся во flash без шифрования. Используйте доверенную локальную сеть. TLS защищает соединение с MQTT-брокером, а не браузерный интерфейс.

## Интерфейс и OLED

| Раздел | Возможности |
|---|---|
| Обзор | Давление, измеримый диапазон, состояния датчика, Wi-Fi и MQTT, напряжение, АЦП, RSSI и память |
| Подключение | Поиск и сохранение Wi-Fi, MQTT, Discovery, TLS, загрузка и удаление CA |
| Калибровка | Четыре коэффициента и предварительный расчёт диапазона |
| Устройство | Идентификатор, версия, IP, время работы, имя, пароль, OTA и перезапуск |

Интерфейс адаптируется к телефону и компьютеру. Тема сначала следует системе, затем сохраняется в браузере. Ресурсы локальные; интернет и CDN не нужны.

Опрос статуса выполняется с паузой 2 секунды после предыдущего запроса, без параллельных запросов статуса. Он останавливается в скрытой вкладке и на время OTA. Через 5 секунд без свежего ответа манометр показывает «—». Загруженные черновики форм не перезаписываются фоновым опросом.

OLED: SSD1306 128×64, I²C-адрес `0x3C`, без отдельного RESET; используются стандартные выводы `Wire` выбранной платы. Настройки находятся в [Config.h](src/Config.h). При отсутствии ответа дисплея остальная прошивка продолжает работу.

Экран обновляется примерно каждые 250 мс. Рабочий режим показывает давление, `W:ok`/`W:--` и `M:off`/`M:ok`/`M:tls`/`M:--`. Ошибки обозначаются `NO SENSOR`, `OVER`, `STALE DATA`. Экран AP показывает SSID, пароль и адрес портала.

## Измерение и калибровка

Один отсчёт A0 берётся примерно каждые **20 мс**. Скользящее среднее использует **32 отсчёта**: номинальное окно 0,64 секунды. После первого отсчёта и паузы от 500 мс окно заполняется свежим значением. Пропущенные измерения не восстанавливаются.

Формулы из [Logic.cpp](src/Logic.cpp):

```text
V = raw / 1023 × adcFullScaleV
P, МПа = (V − vZero) × pFullMPa / (vFull − vZero)
P, бар = P, МПа × 10
Pmax, бар = (min(adcFullScaleV, vFull) − vZero) × pFullMPa / (vFull − vZero) × 10
```

`V` — восстановленное напряжение датчика до внешнего делителя. Настройка `adcFullScaleV` меняет пересчёт, но не допустимое физическое напряжение входа A0.

| Поле | По умолчанию | Пределы |
|---|---:|---|
| `adcFullScaleV` | 3,2 В | 1–10 В; напряжение датчика, соответствующее отсчёту 1023 |
| `vZero` | 0,5 В | Не меньше 0, строго ниже `adcFullScaleV` |
| `vFull` | 4,5 В | Не больше 10 В; `vFull − vZero > 0.1 В` |
| `pFullMPa` | 0,5 МПа | Больше 0, не больше 100 МПа |

Исходная расчётная граница — **3,375 бар**. Коэффициенты по умолчанию не подтверждают соответствие фактическому датчику: проверьте калибровку по опорному давлению. Небольшое отрицательное давление сохраняется.

- `over`: отдельный отсчёт достиг 1020 либо напряжение превысило `vFull + 0.05 В`.
- `fault`: отсчёт отрицательный, напряжение ниже `vZero − 0.2 В` или результат пересчёта неконечный. Флаг характеризует сигнал, не устанавливая однозначно причину неисправности.
- `stale`: выборки ещё нет либо возраст последнего отсчёта достиг 1000 мс.

Кратковременные нарушения проверяются до усреднения. `over` и `fault` снимаются после секунды устойчивого восстановления с гистерезисом; длинная пауза не считается восстановлением. Усреднённое значение также проверяется при чтении.

При любом из этих флагов давление в JSON равно `null`; напряжение и отсчёты остаются доступны. Сохранение настроек и изменение CA переприменяют MQTT и перезапускают фильтр через основной цикл.

## Wi-Fi

SSID: **1–32 байта**. Пароль: **8–63 байта** или пустая строка для открытой сети. Прежний пароль можно сохранить только для того же SSID.

Менеджер хранит копию SSID/пароля в RAM. Перед начальным подключением, сменой сети и принудительным повтором он очищает текущую конфигурацию SDK только в RAM, выключает STA, ждёт не менее **200 мс после фактического выключения** без `delay()`, затем включает STA с явными SSID/паролем, без фиксации канала и BSSID. Резервная AP и профиль во flash сохраняются.

Успех требует `WL_CONNECTED` и ненулевого IP. Если SDK не восстановил связь самостоятельно за 30 секунд, подготовка STA повторяется. Flash обновляется при применении сети с портала; обычные повторы используют RAM. После получения IP заново запускаются HTTP и mDNS.

AP предлагается после 15 секунд отсутствия связи. При сохранённой сети она закрывается через 180 секунд без клиентов. Без сохранённой сети этот таймаут не применяется. После подключения к роутеру AP закрывается без клиентов, когда с её запуска прошло больше 10 секунд. Закрытие AP не останавливает STA-повторы; новое окно настройки можно открыть перезапуском устройства.

## MQTT и Home Assistant

Пустой адрес брокера выключает MQTT. Client ID — `wps_xxxxxx`.

| Поле | Значение по умолчанию / ограничение |
|---|---|
| `mqttHost` | Пусто; DNS-имя или IPv4 без протокола и порта, до 63 байт |
| `mqttPort` | 1883; 1–65535 |
| `mqttUser` | Пусто; до 31 байта, пустое значение означает отсутствие аутентификации |
| `mqttPass` | Пусто; до 63 байт |
| `mqttBase` | `watersensor/wps_xxxxxx`; непустая строка до 63 байт |
| `mqttIntervalS` | 10 секунд; целое 1–3600 |
| `haPrefix` | `homeassistant`; до 31 байта, пусто выключает Discovery |
| `deviceName` | `Water Pressure`; непустая строка до 31 байта UTF-8 |

База и префикс не допускают `+`, `#`, управляющих символов и завершающего `/`. Строковые пределы считаются в байтах UTF-8.

Пустое поле пароля в браузерной форме сохраняет секрет; флажок удаления очищает его. В API отсутствие `mqttPass` сохраняет значение, явное `"mqttPass":""` удаляет.

```text
<mqttBase>/state                                  JSON, без retain
<mqttBase>/status                                 online/offline, retain
<haPrefix>/sensor/<deviceId>/<entity>/config        Discovery, retain
```

Брокеру задаётся Last Will `offline`. После подключения отправляются `online`, Discovery и свежие показания; далее состояние публикуется по `mqttIntervalS`. Публикации имеют QoS 0.

Discovery создаёт `pressure`, `voltage`, `rssi`, `raw` со сроком актуальности `3 × mqttIntervalS + 10` секунд. При смене префикса старые retained-конфигурации удаляются. Ошибки публикации или сохранения приводят к повтору через 10 секунд; прежний применённый префикс хранится до завершения операции. Успешный `publish()` не подтверждает хранение брокером. При смене брокера записи на старом брокере нужно удалить отдельно.

Первая попытка соединения выполняется сразу после появления Wi-Fi. После неудач пауза растёт до 30 секунд и отсчитывается от конца попытки. CONNACK 1, 2, 4 и 5 останавливают повторы до переприменения настроек; 3 и транспортные ошибки считаются временными. Serial сообщает этап, код, адрес, причину и действие, не печатая MQTT-пароль.

### TLS

| `mqttTlsMode` | Режим |
|---:|---|
| 0 | Незашифрованный TCP |
| 1 | TLS без проверки подлинности брокера |
| 2 | TLS с SHA-1 отпечатком сертификата |
| 3 | TLS с CA, проверкой имени и срока сертификата |

`mqttFingerprint`: 40 hex-символов либо 20 пар через двоеточия, без пробелов. Ошибочный отпечаток и неизвестный режим блокируют подключение без автоматического понижения защиты.

Для CA загрузите корневой PEM **1–4096 байт**, используйте имя брокера из сертификата и доступный сервер времени. `ntpServer` содержит до 63 байт; пусто означает `pool.ntp.org`. До установки часов режим CA ждёт NTP. Форма переключает стандартные порты 1883/8883 при смене TLS; нестандартный порт сохраняется.

Проба MFLN определяет запрошенный приёмный буфер: 1024 байта при положительном результате, иначе 16384. Передающий буфер — 512 байт. Проверяется крупнейший свободный блок: минимум 9000 или 23000 байт соответственно. Это не полный размер всех выделений BearSSL.

**Подключения MQTT/TLS синхронные.** DNS, TCP, MFLN и TLS могут приостанавливать HTTP, OLED и выборку. Константы таймаутов не задают гарантированную общую длительность. Регистрация коротких гидроударов не гарантируется.

## HTTP API

Базовый адрес — IP устройства, порт 80. JSON использует `Content-Type: application/json`. Все POST требуют `X-WPS-Request: 1`. Сессия передаётся cookie `wps_session` с `HttpOnly`, `SameSite=Strict` и сроком один час. CORS не включён.

| Метод и путь | Сессия | Назначение |
|---|---|---|
| `GET /reading` | Нет | Показания в формате MQTT |
| `GET /api/status` | Нет | Показания, соединения, версия, ошибки и состояние входа |
| `POST /api/login` | Нет | `{"password":"…"}`; создаёт cookie |
| `POST /api/login/display` | Нет | `{"visible":true}` продлевает показ OLED на 60 секунд, `false` скрывает |
| `POST /api/logout` | Да | Завершает сессию |
| `GET /api/settings` | Да | Настройки без секретов, `mqttPasswordSet`, `wifiSsid` |
| `POST /api/settings` | Да | Частичное транзакционное обновление |
| `POST /api/wifi` | Да | `ssid`, `password`, необязательный `keepPassword` |
| `POST /api/wifi/scan` | Да | Запуск поиска |
| `GET /api/wifi/scan` | Да | `running`, до 20 сетей с `ssid`, `rssi`, `secure` |
| `POST /api/ca` | Да | Multipart-файл; браузер использует поле `certificate` |
| `POST /api/ca/delete` | Да | Удаление CA и переприменение MQTT |
| `POST /api/firmware` | Да | Ровно один multipart-файл; поле браузера `firmware` |
| `POST /api/restart` | Да | Перезапуск после ответа |
| `GET /api/diagnostics/wifi` | Да | NDJSON; только диагностическая сборка |

Действия возвращают `message` либо `error`. Ошибки параметров дают 400, отсутствие сессии — 401, служебного заголовка — 403, частый вход — 429, ошибка сохранения настроек — 507. Невалидный patch не применяется частично. JSON ограничен 2048 байтами в обработчике; это не ограничивает предварительную буферизацию тела в ESP8266WebServer.

```json
{"bar":2.55,"mpa":0.255,"volt":2.540,"raw":812,"rssi":-58,"over":false,"fault":false,"heap":24568,"raw_instant":813,"age_ms":8,"stale":false}
```

`raw` — средний отсчёт, `raw_instant` — последний, `volt` — напряжение датчика до внешнего делителя, `age_ms` — возраст выборки, `heap` — свободные байты памяти. `/api/status` помещает объект в `reading` и дополнительно возвращает `max_bar`, `heap_block`, `storage_error`, `tls_error`, состояния соединений и `login_password_visible`. Последнее поле означает временный режим показа, не подтверждая наличие OLED. `uptime_s` основан на `millis()` и обнуляется также при его переполнении примерно через 49,7 суток.

API настроек допускает поля из таблиц MQTT, TLS и калибровки, а также `portalPass`. Внутренний `haPrefixApplied` изменять нельзя. Отсутствующие поля patch остаются прежними; неизвестные поля, неверные типы, превышение длины и неконечные коэффициенты отвергаются.

## Постоянное хранение

LittleFS хранит `/config.json` и CA `/ca.pem`. Временные файлы — `/config.tmp` и `/ca.tmp`. Профиль Wi-Fi хранится отдельно средствами SDK.

Настройки сначала сериализуются во временный файл. Проверяются ожидаемый и фактический размеры, разбор JSON и точное совпадение записанных байтов; затем выполняется `rename`. RAM-настройки заменяются только после успешного сохранения. При загрузке старых файлов отсутствующие поля сохраняют значения по умолчанию. Некорректные коэффициенты исправляются, а ошибки TLS не превращаются автоматически в небезопасный режим.

CA проверяется по размеру и разбирается BearSSL до замены. Ошибки записи, отмена, неверный сертификат и ошибка переименования сохраняют прежний CA.

Существующая LittleFS при ошибке монтирования автоматически не форматируется. Форматирование допускается только для полностью стёртого раздела. При недоступном хранилище прошивка использует временные настройки и сообщает ошибку.

## OTA из браузера

1. Соберите `pio run -e d1_mini`.
2. Войдите и откройте **Устройство → Обновление прошивки**.
3. Выберите `.pio/build/d1_mini/firmware.bin`, подтвердите загрузку и дождитесь ответа.
4. После восстановления связи проверьте версию. Если ответ потерялся, проверьте её перед повторной загрузкой.

Принимается обычный несжатый BIN данного проекта, созданный `elf2bin.py` закреплённого Core 3.1.2. Gzip, пустой файл, несколько файлов в запросе, неверный заголовок, лишние байты, усечённый образ и неверная CRC32 отвергаются.

Проверка потоковая, с постоянным расходом RAM: сверяются заголовки, встроенная полная длина и CRC32 всего полученного образа. При расчёте CRC поля размера/CRC считаются восемью нулевыми байтами согласно формату Core. Дополнительный манифест не нужен. CRC обнаруживает повреждение, но **не является цифровой подписью** и не подтверждает автора прошивки.

Запись идёт в свободную область OTA. Команда установки Updater создаётся только после проверки полного образа и повторной проверки сессии. При отмене, ошибке и истечении сессии Updater явно закрывается без установки с освобождением буфера. Один байт ёмкости резервируется, чтобы отмена не могла подтвердить полностью заполненное обновление. Во время установки не отключайте питание.

Обычная USB-загрузка и OTA с прежней разметкой flash сохраняют настройки и CA. Полное стирание flash и загрузка файловой системы их не сохраняют.

## Ограничения текущей реализации

- Синхронные сетевые операции нарушают регулярность выборки и обновления экрана. Жёсткой гарантии периодов 20/250 мс нет.
- В Core 3.1.2 `setTimeout()` используемой TLS-обёртки не меняет TCP-таймаут внутреннего контекста. Значение 3000 мс из конфигурации не является фактическим пределом этого этапа TLS.
- Отрицательная MFLN-проба кэшируется до переприменения настроек. После временного сбоя пробы при нехватке большого непрерывного блока для новой пробы потребуется сохранить настройки или перезапустить устройство.
- Штатное отключение MQTT не публикует отдельный `offline`; прежний retained-статус может остаться `online`. В HA актуальность показаний дополнительно ограничена `expire_after`.
- Уже работающая AP не меняет пароль при сохранении нового. Для однозначного применения и достоверной подсказки AP перезапустите устройство.
- Точность датчика, радиосвязь и восстановление после перезапуска конкретного роутера требуют стендовых проверок. Native-тесты этого не подтверждают.

## Разработка и проверки

| Путь | Назначение |
|---|---|
| `src/main.cpp` | Инициализация и основной цикл |
| `src/Logic.*`, `src/Sensor.*` | Формулы, фильтр, валидация, JSON, Discovery и чтение A0 |
| `src/Settings.*`, `src/CaStore.*` | Постоянное хранилище |
| `src/WifiConnection.*`, `src/Mqtt.*` | STA, MQTT/TLS и повторы |
| `src/Portal.*` | HTTP, сессии, AP, загрузки и применение настроек |
| `src/FirmwareImage.h`, `src/FirmwareUpload.*` | Проверка BIN и жизненный цикл OTA |
| `src/LoginDisplay.h`, `src/Display.*` | Срок показа пароля и OLED |
| `src/WifiDiagnostics.*` | Условно компилируемый журнал Wi-Fi |
| `web/`, `scripts/`, `test/` | Интерфейс, инструменты и native-тесты |

```sh
pio test -e native
pio run -e d1_mini -e d1_mini_diag
python scripts/verify_nonos_sdk.py
python scripts/verify_nonos_sdk.py --environment d1_mini_diag
```

Native-сборка компилирует `Logic.cpp`; отдельные тесты дополнительно включают производственные модули хранения, Wi-Fi и OTA с заглушками. Покрыты ошибки записи, транзакционность, переполнение `millis()`, повреждение/отмена OTA, освобождение буфера и срок показа пароля. CA-заглушка не проверяет криптографическую корректность PEM; заглушки Updater и Wi-Fi не заменяют испытания flash и радио.

`verify_nonos_sdk.py` читает готовые ELF/BIN/map, проверяя реальный `SDK_VERSION` и происхождение 11 SDK-архивов. CI запускает native-тесты, обе сборки и обе проверки SDK.

### Предпросмотр и браузерный тест

```sh
python scripts/preview.py
```

Откройте `http://127.0.0.1:8765/`, пароль **`preview-access123`**. Сервер явно показывает тестовые данные и не управляет платой. Другой порт задаётся `--port`.

Для smoke-теста нужны Node.js, Google Chrome и доступный модуль `playwright`:

```sh
node scripts/ui_smoke.cjs
```

По умолчанию используется предпросмотр на порту 8765; другой адрес — `WPS_PREVIEW_URL`. Проверяются четыре раздела, обе темы, пять ширин, формы, парольный интерфейс и восстановление отображения. Скриншоты сохраняются в `.pio/ui-review/`. Продление показа пароля проверяется с управляемыми часами браузера.

### Диагностика Wi-Fi

```sh
pio run -e d1_mini_diag
python scripts/capture_wifi_diagnostics.py --url http://DEVICE_IP --duration 900
```

Команда сборки не устанавливает диагностический образ на устройство. Сборщик запрашивает пароль без отображения, читает статус и журнал; его результаты сохраняются в `.pio/hardware/wifi-diagnostics-*`. Подробности: [WIFI_DIAGNOSTICS.md](docs/WIFI_DIAGNOSTICS.md), [NONOS_SDK_3.0.5.md](docs/NONOS_SDK_3.0.5.md).

Документы [docs](docs) содержат исторические испытания 3.0.x и 3.1. Их результаты, хеши и ограничения относятся к указанным версиям и не переносятся автоматически на 3.1.1.
