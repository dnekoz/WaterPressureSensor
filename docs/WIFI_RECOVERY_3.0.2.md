# Восстановление Wi-Fi в 3.0.2

Исправление от 18.10.2026 на базе версии 3.0.2; номер версии сохранён.

Ранее резервный механизм каждые 30 секунд вызывал `WiFi.reconnect()` без проверки
результата. В установленном ESP8266 Arduino Core 3.1.2 этот метод вызывает SDK
disconnect/connect, но не перезапускает STA и не задаёт конфигурацию заново.
Точную причину отказа на пользовательском роутере без аппаратного воспроизведения
установить нельзя; исправление добавляет восстановление после застревания этого пути.

Теперь `WifiConnection` хранит ограниченную копию SSID/пароля в RAM. Штатное
автовосстановление SDK остаётся включено. Через 30 секунд без соединения модуль
выключает только STA, а через 100 мс рабочего цикла включает его и вызывает
`WiFi.begin(ssid, password, 0, nullptr)`. Новый поиск не фиксирует прежний канал/BSSID.
При неудаче попытки продолжаются, включая период после закрытия резервной AP.
Данные не стираются; flash обновляется только при сохранении новой сети на портале.
После получения IP портал заново запускает HTTP/mDNS и DNS резервной AP, если она
активна. MQTT использует существующий механизм восстановления.

## Проверки

- Полный набор native-тестов с первыми 10 Wi-Fi-сценариями: 148/148.
- После проверки ещё одного случая с включением STA при закрытии AP повторно
  выполнен весь набор `test_wifi`: 11/11, без предупреждений компилятора.
  Итого проверены 138 существующих и 11 новых сценариев.
- Новый модуль проверен cppcheck: warning/performance/portability, без замечаний.
- Исходники приложения собираются с `-Wall -Wextra` и дополнительным `-Werror`
  через `PLATFORMIO_BUILD_SRC_FLAGS`. В сторонней PubSubClient 2.8 остаётся прежнее
  предупреждение `-Wsign-compare`; эта библиотека не изменялась.
- Окончательная сборка `d1_mini`: RAM 43 220 / 81 920 байт (52,8%), flash
  приложения 573 063 / 1 044 464 байт (54,9%); BIN 577 216 байт.

Тесты компилируют настоящий `WifiConnection.cpp` с подменой аппаратного Wi-Fi API.
Покрыты длительное отсутствие роутера, закрытие AP по таймауту, повторная потеря
связи после длительной работы, нормальное автовосстановление SDK, ошибки переключения
STA, отказ disconnect, изменение настроек во время повтора, открытая сеть, отсутствие
сохранённого SSID, исчезновение текущей конфигурации SDK и переполнение `millis()`.
Радиосвязь, DHCP, доступность HTTP/mDNS и MQTT на настоящей плате требуют испытания.
В ходе этого исправления плата не прошивалась и роутер не отключался.

## Испытание на устройстве

1. Установить собранную прошивку обычным способом. После подключения записать IP
   и открыть USB Serial 115200. Убедиться в наличии `[WIFI][OK]` и работе интерфейса.
2. Выключить роутер на 60 секунд. Ожидаются `[WIFI][LOST]`, резервная AP примерно
   через 15 секунд и затем `[WIFI][RETRY]` / `[WIFI][CONNECT]` раз в 30 секунд.
3. Включить роутер и дождаться готовности его Wi-Fi/DHCP. Ожидать `[WIFI][OK]`
   после очередного подключения; проверить интерфейс по указанному в Serial IP,
   затем имя `.local` и восстановление MQTT, если брокер включён.
4. Повторить с отключением больше четырёх минут: закрытие AP через 180 секунд
   не должно останавливать попытки STA. Затем повторить короткое отключение.
5. При необходимости проверить подключение телефона к резервной AP во время
   отсутствия роутера и восстановление после смены его канала 2,4 ГГц.

При отказе сохранить журнал от `[WIFI][LOST]` до попыток после запуска роутера.
Строка `[WIFI][CONNECT]` означает начало попытки, а не успешное подключение;
успех подтверждает только `[WIFI][OK]` с полученным IP. После перезагрузки роутер
может выдать устройству другой IP.
