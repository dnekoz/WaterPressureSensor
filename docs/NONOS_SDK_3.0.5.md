# NON-OS SDK 3.0.5 / прошивка 3.0.3

Используется штатный **NON-OS SDK 3.0.5**, поставляемый с Arduino Core 3.1.2
в PlatformIO `espressif8266@4.2.1`. Флаг
`PIO_FRAMEWORK_ARDUINO_ESPRESSIF_SDK305` выбирает библиотеки `NONOSDK305`
и соответствующий SDK3 ABI. Библиотеки SDK отдельно не скачиваются,
глобальная установка PlatformIO не изменяется. RTOS SDK не используется.

Фактическая строка `ESP.getSdkVersion()` — **`3.0.5(b29dcd3)`**.
Она выводится при старте в Serial и в `/api/status` полем `sdk`.
Поле `sdk_release` равно `3.0.5`.

```sh
pio run -e d1_mini
python scripts/verify_nonos_sdk.py
pio test -e native
```

Проверка читает настоящий символ `SDK_VERSION` из ELF, проверяет строку
версии в BIN и происхождение библиотек по карте линковки.

Обычная сборка — `3.0.3`, отдельная диагностическая —
`3.0.3-diag-sdk305` (`pio run -e d1_mini_diag`). Диагностика описана в
[WIFI_DIAGNOSTICS.md](WIFI_DIAGNOSTICS.md).

## Сетевое поведение

Сохранены штатные повторы подключения каждые 30 секунд и работа измерений
при отсутствии сети. Исправлена ошибка резервной AP: в конце цикла её возраст
считается по свежему `millis()`. Ранее запуск AP мог занять время, и разность
старой отметки времени с более новой превращалась в большое беззнаковое число.
Точка доступа из-за этого немедленно закрывалась, а повторно не предлагалась.

Сборка 3.0.6 была испытана и отклонена: приложение запускалось, но подключение
заканчивалось таймаутом WPA `reason=204`. Штатная 3.0.5 на том же устройстве
с теми же настройками успешно подключилась к Wi-Fi и MQTT/TLS. По решению
пользователя в проекте оставлена 3.0.5; экспериментальная подмена библиотек
3.0.6 удалена. Устранение исходного отказа после перезапуска роутера нужно
отдельно подтвердить на установленной обычной прошивке.

## Установка и откат

Обычный `firmware.bin` устанавливается через USB или обновление в веб-интерфейсе.
Разметка flash и LittleFS сохранены: стирать flash или загружать файловую
систему не требуется. Сохранённые настройки и CA остаются на месте.

На рабочем компьютере исходный бинарник 3.0.2 находится в
`.pio/hardware/firmware-3.0.2-before-wifi-diag.bin`, SHA-256:
`7b9f3b0738af1aa9bc209e745d19ce0b894c4cff8d42ac59e4df2ef25faaa3f0`.
Полный образ flash перед USB-диагностикой сохранён отдельно:
`.pio/hardware/flash-before-sdk306-usb.bin`, SHA-256:
`bbef483452ab390b332368fd30320632c9dccce4984af3670a6f99d7decb243b`.
Эти локальные артефакты исключены из Git.

## Проверка на устройстве 24 октября 2026

Обычная прошивка 3.0.3 загружена по USB на Wemos D1 mini `wps_24728b` (COM6).
Строка SDK подтверждена USB-журналом запуска и `/api/status`:
`3.0.5(b29dcd3)`. Wi-Fi восстановился на прежнем IP `192.168.1.69`,
MQTT подключился с TLS. Настройки из API после обновления и после
программного перезапуска полностью совпали со снимком до обновления.

В Chrome проверены вход, четыре раздела, обе темы на ширине 390 и 1440 px,
отсутствие горизонтального переполнения и ошибок JavaScript.
Перезапуск из веб-интерфейса выполнен успешно: после него снова доступны
HTTP, Wi-Fi и MQTT/TLS. Обычная прошивка не содержит диагностического журнала.

Обе сборки прошли проверку ELF/BIN и происхождения SDK; 138 native-тестов
прошли. Итоговый SHA-256 обычной прошивки:
`b02801cba92f7940159e6986da8072409a3f54604cd094549e18fea6d9e77028`.
Копия: `.pio/hardware/firmware-3.0.3-sdk305.bin`.
Размер обычной сборки: RAM **43 652 байта**, flash **580 179 байт**.
Локальные результаты: `sdk305-final-boot.txt`, `sdk305-final-status.json`,
`sdk305-final-check.json`, `sdk305-final-desktop.png`, `sdk305-final-phone.png`
в `.pio/hardware/`.

Исходный отказ после отсутствия сети 1–2 минуты на этой обычной прошивке
пока не воспроизводился: перезапуск самого датчика не заменяет перезапуск роутера.
